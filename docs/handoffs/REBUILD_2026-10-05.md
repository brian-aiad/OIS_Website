# Original Insurance rebuild — October 5, 2026

## Delivery status

Local rebuild of the complete website. Production has not been deployed as part of this report. The development preview is `http://localhost:3002`; deployment remains exclusively through `bash scripts/deploy.sh` from the repository root. No ranking, indexing, or customer-acquisition improvement is claimed before publication and measurement.

## What changed

- Replaced the React/Vite application and client-rendered page replacement with Astro **7.3.5**, TypeScript, static HTML, and intentional vanilla JavaScript. The inspected repository was not an existing Astro application. Stable package availability and Astro migration requirements were checked before selecting the version.
- Rebuilt the homepage, five coverage guides, twelve service-area pages, services catalog, about, contact, office/directions, FAQ, privacy, accessibility, quote utility, and 404 experience.
- Established an ivory, navy, muted-gold, and sage visual system using Newsreader and DM Sans, shared spacing/type/button/form tokens, and responsive page-family layouts. Kept the hero direction the owner liked, then made coverage imagery and section treatments match it.
- Created California editorial hero artwork and matching auto, home, commercial-vehicle, and document illustrations, plus code-native coverage diagrams and supporting visual details. Real office photographs remain evidence of the actual business. Responsive AVIF/WebP outputs, dimensions, and lazy loading reduce image cost and layout movement.
- Replaced vague product presentation with clearer service names and practical explanations. Tightened oversized gaps and repeated decorative sections while retaining readable separation. Removed unsupported savings, timing, carrier-count, coverage, and compensation claims, including a visible Spanish drafting note inherited from old copy.
- Added purposeful entrance, image, line, menu, accordion, button, and page-transition effects with reduced-motion alternatives. Content remains available without animation or JavaScript.
- Rebuilt desktop and mobile navigation, focus behavior, footer, service exploration, contact channels, and conversion links. Testimonials use existing repository content; no fabricated ratings, carrier logos, or customer claims were added.
- Preserved **Quotzal** at `https://quotzal.com/f/original-insurance`. Quote buttons use a responsive lazy-loaded dialog; `/quote` provides a dedicated embedded experience and direct-provider fallback. Web3Forms remains the general contact form, not a replacement quote backend.
- Changed the public email to **contact@originalinsurance.net**. This source change does not provision the mailbox or change the Web3Forms recipient account.
- Retained GA measurement identity, Vercel analytics/performance integration, phone/text links, business details, existing route rules, API handling, and Vercel project linkage. Added immutable caching for hashed Astro assets; removed obsolete framework code and dependencies.

## SEO and information architecture

- Static titles, descriptions, canonical tags, Open Graph/Twitter metadata, and meaningful page content do not depend on client JavaScript.
- Sitemap remains 25 canonical URLs. Internal links preserve established paths; unknown URLs must not become homepage soft 404s.
- Schema includes WebPage/AboutPage/ContactPage, the homepage WebSite identity, breadcrumbs on indexable non-home pages, and InsuranceAgency only on permitted page families. **Five Service entities** describe the five visible coverage guides.
- No FAQPage, Review, AggregateRating, SearchAction, or invented public-search markup is emitted. Visible FAQs and testimonials remain useful without those schemas.
- The physical address remains in Downey on every city page; service-area pages do not claim branch offices. No fake prices, rankings, local statistics, credentials, or carrier partnerships were introduced.
- Primary California DMV/CDI consumer resources support coverage explanations. Business review of rewritten insurance content is still required; website update dates must not imply completed professional approval.
